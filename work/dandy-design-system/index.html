Design system · 2025 – now · Sole product designer

I built a design system from scratch for the tool that makes every restoration possible.

Dandy Design Center had no design system. I built one in Storybook, with Cursor, on real production code.Storybook · Cursor · Claude

01 · The gap

Chairside had a design system.

Its system, Floss UI, was fully built in Figma and live in code, for the dentist-facing product.

Dandy Design Center had none.

Software for designing 3D restorations, essentially Figma for teeth. A very different product, with a very different architecture and front end.

  • ✕Component library
  • ✕Documentation
  • ✕Design tokens

So I built one from scratch.

In Storybook, with Cursor, on real production code, for the tool that makes every restoration possible.

02 · The users

Engineers, PMs, and designers were my end users.

Each needed something different from the same system.

  • </>EngineersCopy-ready code and handoff docs
  • ◎Product managersOne place to see what exists and what is new
  • ▦DesignersA browsable taxonomy with every state

03 · The build

Reuse what exists, build what is new.

I reused Floss UI components wherever I could and created many net new ones, using Cursor, referencing our production code, and hosting it all in Storybook.

Tag every component.

New, existing, or exploring. A status on everything makes reuse the default.

One taxonomy.

IA rules decide where each component lives, so the whole system can be browsed in one place.

Every state, with code to copy.

Each component page has all of its states and a ready-to-paste snippet.

A page, not a meeting.

A handoff guide and Jira templates cover where the source lives, how it ships, and how to measure success.
