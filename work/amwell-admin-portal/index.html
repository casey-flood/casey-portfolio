Amwell · Senior Product Designer · 3-week sprint

From “make it faster” to a platform that scales.

Amwell’s admin portal was fragmented and hard to navigate. I redesigned it as one role-based system, and task completion rose from 45% to 82%.Figma · User testing · Converge design system

01 · The context

The admin portal is the control hub.

Amwell connects patients and providers for virtual visits. The admin portal is where healthcare organizations configure the experience both sides see: service lines, provider networks, clinical rules, and patient access.

Two kinds of admins, four roles.

Amwell’s own implementation managers and NOC agents build and support the platform. Clients like CVS Health, through their health system admins and IT teams, manage their own instance.

My role: Senior Product Designer, 3-week sprint.

I led design, with a couple of other designers, alongside PM, engineering, and architecture. Amwell was also moving to its modular Converge UI framework, so this was the moment to modernize the admin experience.

02 · The problem

Leadership asked to “make it faster.”

The portal had become a major pain point, used by internal teams and clients like CVS Health and Cleveland Clinic. The real problem was a complex, outdated structure that made even small tasks cumbersome.

Navigation was behind a third of support tickets.

Across 400+ users, support tickets tied to navigation and workflow inefficiencies were piling up.

30% of support tickets tied to navigation and workflow

Tickets, shadowing, and interviews.

We analyzed 3 months of support tickets, ran 5 shadowing sessions and 8 contextual interviews, and mapped workflows across the departments that touch the portal. Three pain points surfaced: navigation confusion, unclear role-based access, and task completion barriers.

“I spend more time figuring out how to do things than actually doing them.”

Admin, contextual interview

Three roles, three very different needs.

Implementation managers configure everything across many clients. NOC specialists troubleshoot the whole platform. Health system admins only care about their own organization.

Three tiers of access.

Amwell super admins, tenant super admins, and tenant basic admins each need a different slice of the same system.

03 · What we found

Admins lost 40% of their time switching tools.

Different roles needed different information hierarchies, but everyone got the same sprawling structure.

40% of admin time spent switching between tools

No clear paths meant 2+ weeks of training.

And the jargon was inconsistent: doctor, provider, and clinician; tenant, instance, and client. Same thing, different words.

Two focus areas.

A dashboard that is a snapshot of the most important features. And a navigation framework that is intuitive, scalable, and gets people to features, configurations, and tools quickly.

Who can do what, mapped.

A permissions matrix made every capability explicit, so the interface could show each admin only what applies to them.

04 · The options

Align on language first.

UX audit and terminology workshops across 8 departments produced a standard enterprise dictionary, then a refined sitemap.

Option 1: separate interfaces.

Different entry points per admin type. Clear separation of concerns, but users with multiple roles would need multiple logins, and engineering would maintain multiple codebases.

Option 2: permission toggles.

One interface with switches. Simpler to maintain, but users found switching context confusing, and it was inefficient for super admins.

Option 3: a contextual interface. Selected.

Dynamic global navigation for super admins, context-aware components by user type, and progressive disclosure by role. One codebase, built from reusable components, that scales to new roles and features.

05 · The build

Feedback every day, from every side.

Daily check-ins with engineering, rapid prototype testing, feasibility reviews, stakeholder email threads, and unmoderated testing kept the design honest.

“I find it intuitive to access my global nav settings and I like the clear distinction between those settings and settings for tenant level.”

Admin, usability test

Wireframes first, then cut what didn’t matter.

The first dashboard was a customizable home for super admins. As we iterated, we learned admins don’t ordinarily open that data, so the dashboard got lighter.

Built on the existing design system.

We moved from rough wireframes to Amwell’s provider and patient components for consistency. Desktop first, since 99.8% of admins use desktop.

Introducing the “collapse-rator.”

A scalable side menu that expands and collapses with accordion sub-pages for multi-step processes. 65% of admins found the old static sidebar overwhelming.

Built to scale in code.

Context management, dynamic component rendering, permission management, and feature flags, so one codebase serves every role.

A dark mode for long sessions.

Admins live in this tool all day. The final system shipped with a dark mode designed to the same standards.

06 · The final designs

For the Amwell super admin: a global view.

A tenant list with search and add. Global navigation to every tenant, patient, provider, and device.

Never lose your place.

Global search stays available inside a tenant, and breadcrumbs show how you got there.

For the client super admin: just their tenant.

No global nav, because they don’t need it. Client-specific navigation and an audit trail show when information last changed.

Add and configure service lines.

Super admins add service lines within their organization and change their configuration.

The same system, more screens.

Service line details, a guided add flow, patients, and practitioners, all from the same components.

For tenant admins: manage, not add.

Department managers manage service lines, configure workflow and branding, and see only what applies to them. Help desk staff get view-only access.

07 · The impact

Admins finished their tasks.

Task completion rose with role-based access controls and a navigation framework built for each admin.

45% → 82% task completion rate, user testing

New admins ramped faster.

Clear pathways for common tasks cut the onboarding time for new admins.

30% faster admin onboarding

Fewer mistakes.

Role-based access meant admins only saw what applied to them.

34% fewer configuration errors

Clients went live sooner.

A predictable system made client setup quicker for implementation teams.

25% faster client implementations

Eight teams, one vocabulary.

The terminology workshops aligned eight internal teams on the same words for the same things.

8 internal teams on unified terminology

08 · Reflection

Enterprise UX runs on shared words.

As project lead, I learned that aligning cross-functional teams on basic definitions unlocks faster development and adoption.

One framework, many users.

Thoughtful information architecture can serve very different needs while still scaling. The navigation framework proved it, from basic support views to complex multi-tenant configurations.
